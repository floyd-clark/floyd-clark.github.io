# Private visit log and email alerts

The public page is static. This owner-operated Google Apps Script web app records each successful page-open request in a private Google Sheet and sends an email to the fixed recipient in `Code.gs`. The browser supplies event ID, page path, referrer origin, user agent, language, time zone, viewport, and a temporary tab session ID. Google Apps Script does **not** expose the visitor IP address or verified personal identity to this web app. These fields are self-reported and can be spoofed; a private browser can suppress the session and referrer. It does **not** enforce access or alert on requests blocked by browsers, extensions, connectivity, or mail quotas. Reloads and non-human browser loads can generate alerts. The public endpoint can be forged; its page parameter is only a filter, not authentication.

1. In the owner's Google account, create a standalone Apps Script project named `Signal Intelligence Visitor Alerts`. Paste `Code.gs` into its editor. Keep this project separate from the previous approval service. In Project Settings → Script properties add `ALERT_EMAIL` with the owner's desired private recipient address; never commit its value.
2. Deploy → New deployment → Web app. Execute as **Me**; access **Anyone**. Authorize the mail and spreadsheet scopes requested by this project. Copy its `/exec` URL. The service creates a private `Signal Intelligence Private Visits` spreadsheet after the first request and stores its ID in Script Properties.
3. Set `VISIT_ALERT_URL` in `../visit-alert.js` to that URL, then publish `../index.html` with `<script src="visit-alert.js?v=1" defer></script>` in the head.
4. Open the live page once in a fresh browser tab and check the recipient inbox for `Signal Intelligence page opened` and the new private spreadsheet for the matching event ID. An email and matching row are the delivery test; an opaque browser request alone is not proof of delivery.

Do not put a Google password, OAuth token, spreadsheet ID, or secret in GitHub Pages. The web app URL is public by design. If you require actual authorization before viewing private data, host that private layer behind server-side authentication; this alert is not a gate.
